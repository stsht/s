BRAND / DESIGN PRINCIPLES
-------------------------
- StarShots identity: monochrome ink and pure white, plus restrained cool-grey surfaces.
- Light canvas: clean white with a subtle neutral fade; dark canvas: near-black / charcoal, not rainbow glassmorphism.
- UI font stack: existing Plus Jakarta Sans stack from app-base.css. Do not add Instrument Serif / Google Sans dependencies for this client delivery experience.
- Current soft row surfaces from PR #157: light #f0f4f9, hover #e8eef5, icon/tag surface #e2e9f2; dark row #202228, dark hover #282a31, dark icon #292b32.
- Keep completed/neutral states quiet. Use contrast for actions the client actually needs to take.
- Do not introduce orange in the new action styling. Existing red rejected/error styling elsewhere is unchanged.

CHECKPOINT 4 — CURRENT CHANGES IN PR #158
-----------------------------------------
1) src/pages/g/main.jsx
- The public delivery greeting and password-gate greeting now render the actual client name in a dedicated span, separate from the existing "Hello, [honorific]" prefix.
- Visible greeting wording is preserved. The generic fallbacks ("Your files are ready" / "Hello") remain unchanged.
- This markup separation lets CSS animate the client name only, rather than animating the whole greeting.

2) src/pages/g/g.css
- Greeting typography is refined from weight 600 / letter-spacing -0.035em to weight 500 / -0.02em, keeping the current Plus Jakarta Sans stack and responsive font sizes.
- Only the client-name span receives a one-time CSS gradient transition (~1050 ms): deep navy #263e70 through dark ink #111216 in light mode; restrained navy-blue into pure white in dark mode.
- The name settles to the brand's normal ink/white color; it does not pulse or repeat.
- prefers-reduced-motion disables the animation and shows the inherited static text color.
- The Invoice row gets a subtle thin frame and a solid action pill only when it is not in the existing is-paid state. Pill colors: #111216 with pure white text in light mode; pure white with #111216 text in dark mode.
- The current Invoice action label remains "View" when non-paid. It is intentionally not renamed to "UNPAID": the current UI only marks the row with is-paid versus not-is-paid, and "not paid" can include states other than fully unpaid. This avoids inventing payment semantics.

3) src/pages/g/payment-proof-inject.js
- Uses existing cardMode() values and statuses; no API, upload, locked, or payment decision logic is changed.
- A presentation-only is-action-required class is toggled from the existing action. The solid pill and subtle row frame appear only for Upload / Replace when the proof state has loaded and the UI is not loading or busy.
- Manage ("Waiting for review") and View ("Payment confirmed") remain neutral, without an action pill. That avoids signalling an action while a client is waiting for review or payment is confirmed.
- Light mode action pill is #111216 with #ffffff text; dark mode reverses to #ffffff with #111216 text. The row frame uses a muted navy/white outline.
- No orange is introduced. Existing red error/rejected feedback elsewhere in this file remains unchanged.
